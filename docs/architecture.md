# 架构边界

这份文档记录几条**不随功能改动而变**的边界。新功能先对照这里，再决定写在哪一层。

## 1. 游戏循环在客户端，账号/存档在服务端

```
浏览器
  ├─ 游戏模拟（盖戳、订单、邮路、远行、月光树）
  ├─ localStorage（离线优先，断网也能玩）
  └─ 可选同步 → /api（同源，serve.py 反代）→ moss-sync（Rust / axum）
                     ├─ 注册、登录、会话
                     ├─ 云存档（不透明 JSON + revision）
                     └─ 事件上报
```

- 服务端**不跑游戏 tick**，不认识卡牌、订单或经济系统。规则只有一份，在前端。
- 存档是客户端生成的 JSON blob；服务端只负责鉴权、版本号和持久化。
- 网络失败不能阻塞游玩；同步失败时继续用本地存档，下次再推。

## 1.1 社交边界

镇口只做**元数据社交**：邮差榜、预设明信片、NPC 回信。

- 不存自由文本，减少审核和骚扰面；明信片正文是服务端固定的模板。
- NPC 是服务端种子数据，接口里明确标记 `kind: "bot"`，UI 显示「NPC」，不伪装成真人。
- 礼物是小额的 1–2 墨点/材料，由客户端领奖后写入本地存档；服务端只记录领取状态。不要把它扩展成可交易经济。
- 好友是双向关系：好友码申请 → 接受；好友档案只对好友开放，排行榜不暴露好友码。
- 后院菜地是服务端计时的轻社交：收菜/偷菜由服务端判定，奖励由客户端写入存档；不做资源交易。
- 不做实时聊天或自由信件；如果以后需要，另起服务并单独设计审核/限流。

## 2. Rust 后端：积木，不追大而全

- 当前 `moss-sync` 用 **axum + rusqlite** 自行组装，专注账号/元数据 CRUD。
- 不引入 colyseus-rs：我们没有实时房间、帧同步或状态广播。为了「以后可能」上房间而现在引入，只会增加耦合。
- 如果未来做联机（例如多人同图、实时协作分拣），**另起一个服务** `moss-realtime`：
  - 用 colyseus-rs 或 axum WebSocket 做房间/状态同步；
  - 只通过 token introspection 复用 `moss-sync` 的身份，不共享数据库表；
  - 实时循环与账号/存档 CRUD 分开部署、分开扩缩容。
- 依赖版本保守：`Cargo.lock` 提交；Rust stable；升级单独做，不和功能混在一起。

## 3. 前端：引擎与 UI 框架互不侵入

- 当前游戏是 **DOM/CSS 的卡牌 + 经营 UI**，不是精灵/场景游戏：
  - 不引入 Phaser：把订单、标签页、远征面板搬进 canvas 是倒退；
  - 不引入 React Three Fiber / Babylon：没有 3D 需求；
  - PixiJS 只负责环境粒子，可随时降级关闭。
- 如果未来出现真正的 2D 场景玩法（例如可走的地图小游戏），用 **Phaser 4** 做在**独立 canvas 容器**里，不接管现有 DOM UI；3D 才考虑 Babylon.js。
- UI 框架只做 UI：
  - 推荐 **Vue 3**（渐进、UI 密集、包体适中）用于面板/弹窗/账号界面；
  - 游戏状态放在框架外的 store + 事件总线，逐帧循环不进入框架的响应式系统；
  - 迁移按面板进行，不一次性重写；当前阶段保留原生 DOM 实现，新增复杂 UI 再引入 Vue。
- 构建：Vite + npm，Node 版本由 `.nvmrc` 固定（24），`package-lock.json` 提交。

## 4. 存档与同步语义

- 本地 `localStorage` 是离线时的唯一事实来源。
- 注册：把当前本地存档作为初始 revision 1 上传。
- 登录：以服务器存档为准；若服务器为空，则上传本地存档。
- 日常保存：本地立即写，云端防抖上传。
- 冲突（`409`）：不自动覆盖。玩家选择「云端覆盖本地」或「本地覆盖云端」。
- 服务端 revision 单调递增；不做字段级合并。

## 5. HTTP 部署的威胁模型

线上目前只能走明文 HTTP，所以认证不发送原始密码：

- 浏览器用 PBKDF2-SHA256（100k 轮）从 `密码 + 用户名` 派生 32 字节 verifier；密码只存在于浏览器内存。
- 注册发送 verifier；登录先取一次性 nonce，再发送 `HMAC-SHA256(verifier, nonce)`，proof 不能重放。
- 注册那一次仍会把 verifier 暴露在链路上；拿到它的人可以冒充登录。**首次注册尽量在可信网络完成。**
- Bearer token 仍然会被动可被窃听；拿到 token 就能读存档。30 天有效期是便利与风险的折中。
- 挑战应答防不了主动中间人：HTTP 页面和 JS 本身可被篡改。要真正解决，只能上 TLS（Caddy/Cloudflare Tunnel/平台 HTTPS）。

这些不是“HTTP 已经安全”，而是“在只能 HTTP 的前提下，避免密码明文和最直接的登录重放”。

## 6. 未来的链上收藏品（暂不实现）

如果以后真的要把资产上链，只考虑**装饰性收藏品**，不碰货币、进度和强度：

- 候选：镇口明信片、邮册纪念戳。它们已经有服务端记录（发送者、模板、时间、领取状态），可以作为「来源可验证」的收藏。
- 不能上链：邮票、墨点、材料、卡牌、遗物、远行进度。服务端目前不做权威游戏模拟，客户端存档可被改；把有强度的资产上链会立刻出现复制和作弊。
- 正确顺序：先让服务端成为收藏品发行的事实来源（现在已经在记 `postcards`），铸造资格由服务端签名；钱包只是接收端，不参与游戏循环。
- 钱包接入应使用签名登录（如 SIWE），不要接触助记词，不托管私钥；需要 HTTPS，当前 HTTP 部署不满足。
- 默认保留完全离线的非链上路径；链上只是可选展示/转让，不能成为玩法的前置条件。
- 合规、地区限制、年龄门槛和税务问题需要在上线前单独评估，尤其是面向中国大陆用户时。

## 6.5 交互结构：房间 + 路由

- 页面从「一张长页 + 层层弹窗」改为房间：邮局 / 镇口 / 邮路 / 守夜，桌面左侧导航栏、手机底部导航栏。
- `web/src/router.js` 用 hash 记录房间（`#/hall`、`#/town`、`#/routes`、`#/night`），支持刷新、深链接和浏览器前进后退；`#qa` 启动时不会被改写。
- 邮局保留原有的舞台和三个商店抽屉（邮差 / 信件 / 工坊）以及邮册 / 月亮；镇口承载好友、广场、后院、好友档案和明信片书写；邮路承载发车和远行（准备、战斗、结算都是房间内视图）；守夜承载面板、档案和塔防战斗。
- 主玩法不再用弹窗：镇口、后院、好友档案、明信片书写、远行、守夜都是房间内视图。弹窗只保留账号、帮助、重开/转生确认、选种、随机事件、订单丢弃这类短对话。
- 房间切换会卸载对应的 Vue app；游戏循环、存档和状态机不在 Vue 里。模态打开/关闭不再卸载房间内容（早期迁移时遗留的 `unmountTown` 已移除）。
- 切房间有 240ms 淡入位移过渡（尊重 `prefers-reduced-motion`）；镇口数据在登录后和导航悬停/聚焦时预取（`prefetchTown`），进入时直接复用，避免先看到加载态。
- QA：`qa/rooms.mjs`（`npm run qa`，53 项）覆盖房间切换、hash、镇口注册与三个子视图、双账号加好友与串门、邮路、远行、守夜、过渡动画、手机导航和 console 错误；见 `qa/README.md`。

- 迁移顺序：镇口（已完成）→ 账号（已完成）→ 订单（已完成）→ 邮册（已完成）→ 月亮（已完成）→ 工坊（已完成）→ 远行（已完成）→ 选种 / 好友后院 / 行前准备（已完成）→ 帮助/重开/转生/契约/丢单/随机事件/串门/明信片（已完成）→ 盖戳台；盖戳台保留原生或最后做薄包装。

## 8. 守夜防线（塔防）

- 入口是邮局小店的「守夜」页签；面板显示当前夜、最远记录、植物和融合配方，点「开始守夜」打开宽弹窗。
- 引擎在 `web/src/nightwatch.js`：纯 JS、无 DOM、无全局状态，导出 `createNightWatch({ level, rng, onFinish })`。棋盘 5 条邮路 × 8 格，敌人从右往左走，摸到门板扣血；灯油是场内货币。
- 每一夜的全部波次在开局时一次性生成（`waves`），所以准备页和战斗中都能预览「第一波 / 本波 / 下一波」的敌人构成；生成顺序和旧版不同但重复可玩。
- 植物可以铲掉，返还累计投入的一半灯油（`sell`，含融合投入），用来补救摆位。
- 节奏由 `main.js` 的控制器驱动：弹窗打开时每 70ms 调一次 `tick(0.07)` 并把快照推给 Vue；关闭弹窗、切到后台或暂停时停止。Vue 只渲染快照和回传点击，不参与逐帧逻辑。
- 植物 10 种，按夜解锁：信封草（单发）、邮票花（产油）、彩纸藤（墙）、墨莓（减速）、星屑花（穿行）、月光菇（范围爆）、风铃草（击退）、雨莓丛（中毒）、灯塔花（相邻八格伤害 +25% 光环）、钟楼（全场震波）。
- 融合分两级：基础融合 9 种（连发草 / 邮筒炮台 / 金邮票 / 墨光花 / 月藤 / 风暴信 / 毒墨水 / 灯塔星 / 钟月），同一格再种一株时判定；第 9 夜起融合体还能再和基础植物融合成进阶体（夜班炮台 / 墨海 / 月墙 / 金库 / 星屑连发），每株最多融合两次。
- 新机制：`knockback` 把非 Boss 影子往回推；`poison` 给影子叠持续伤害；`aura` 给相邻植物加伤害（在 `auraBonusFor` 里按周围 3×3 求和）；`global` 的爆发放到所有行。
- 影子 8 种：雾团 / 湿信 / 墨鬼 / 夜蛾（飞）/ 分裂墨团（死后裂成两只小墨点）/ 鼓手（同一行 1.8 格内给同伴 +25% 速度）/ 夜鼠（无视植物，摸到门板偷 40 灯油）/ 夜班车（每 5 夜 Boss）。引擎通过 `notices` 队列把「夜鼠偷油」「夜班车出现」这类事件交给外层 toast。
- 守夜面板分「守夜 / 档案」两视图：档案显示最远夜数、守住次数、打散数、三枚纪念戳状态、16 条词条图鉴，以及最近 20 场记录（夜数、胜负、波次、击杀、相对时间）；记录存在 `nightWatch.history`。
- 融合图鉴：每次成功融合把配方 id 记进 `nightWatch.fusions`（去重）；邮册新增「守夜融合图鉴」14 格，按「已点亮 / 还没合成 / 第 N 夜解锁」展示。合成 8 种和集齐 14 种分别触发两个邮册成就（墙 +2% / +3% 全局产出）。
- 波次与强度按夜增长：夜 HP 倍率 `1 + 0.2·(n-1) + 0.006·(n-1)²`，起始灯油随夜增加，波数封顶 6 波，每 5 夜最后一波加一辆夜班车 Boss。
- 进度只存客户端：`state.nightWatch = { night, best, wins, kills, points, talents, pendingMedals, modifier, history }`，跟存档一起同步；胜利奖励直接加邮票 / 墨点 / 纸 / 蜡。和服务端一样，塔防不是权威模拟，改存档仍可作弊。
- 每日词条：`dailyModifier()` 按本地日序号散列一条规则，池子 16 条（平静夜 / 顺手 / 浓雾 / 油荒 / 急脚 / 潮涌 / 脆纸 / 厚影 / 灯会 / 毒雾 / 顺风 / 回响 / 融合夜 / 雾堤 / 贪夜 / 重影），同一天刷新不变；难词条奖励 +20%~40%，轻松词条 -10% 或不加。词条在开局时传给引擎，作用于射程、灯油、速度、波数、植物生命、影子生命、冷却和奖励倍率。玩家可以花 1 点守夜天赋重摇当天词条，结果按日期存进 `nightWatch.modifier = { day, id }`，同一天刷新/重进都保持；跨天自动回到日历词条。词条可以调整光环倍率、中毒伤害、击退距离、震波伤害、融合花费和波间补油。
- 深雾可以花 1 点守夜天赋重摇下一夜的雾层（`nightWatch.deepChoice = { night, id }`，只对当夜生效）。两个深雾天赋「深灯」「雾墙」各 2 级，分别把深雾的油/冷却惩罚和血/速度加成再减半。
- 深雾：第 16 夜起自动进入，按 `(夜数-16) % 6` 轮流叠一条只加难度的雾层词条（厚 +20% 影子生命 / 疾 +15% 速度 / 旱 -20% 灯油 / 蚀 -15% 植物生命 / 潮 每波 +1 影子 / 钝 +15% 冷却），奖励 ×1.45~1.5；与当日词条叠乘。深雾在 HUD 显示为紫 chip，棋盘变暗，结算和历史记录带「深雾」标记。
- 镇口排行：存档上传时服务端从 `nightWatch.best` 提取最远夜数写进 `users.night_best`（schema v14），`GET /v1/square` 返回，镇口玩家列表展示「N 夜守夜」；NPC 的数值按 id 散列生成。
- 守夜纪念戳：首次守住第 5 / 10 / 15 夜，以及深雾第 20 / 25 / 30 夜时，客户端把等级放进 `pendingMedals`，登录后调用 `POST /v1/nightwatch/claim`；服务端按固定 edition（100 / 50 / 25，深雾 50 / 30 / 15）签发 `nightwatch` 收藏品，序号唯一、不可重复领。未登录时队列留在本地，注册或登录后自动补发。邮册新增「守夜纪念戳」一节。
- 守夜天赋：8 项永久成长（灯芯 / 火漆 / 纸甲 / 门闩 / 油壶 / 快笔各 3 级，深灯 / 雾墙各 2 级），升级花 1/2/3 点。每守住一夜得 1 点，夜数能被 5 整除时额外 1 点。天赋在开局时作为参数传给引擎（`talentBonus`），分别作用于起始灯油、伤害、植物生命、门板上限、自然产油和冷却；不随转生清空。
- 平衡用无头模拟调（直接 import 引擎跑机器人），目标是前 6 夜稳定可过、7–10 夜需要融合和走位。
- `#qa` 下暴露 `__moss.nightwatch*`（快照、加灯油、指定行刷怪、强制胜负、直接放置），供 Playwright 测。

## 9. 版本策略

| 层 | 策略 |
| --- | --- |
| Node | `.nvmrc` 固定 24；`engines >= 20` |
| 前端构建 | Vite 主版本锁在 `package-lock.json`，升级单独提交 |
| Rust | stable + `Cargo.lock`；axum 0.8 系列 |
| 数据库 | `PRAGMA user_version`；v1 匿名表迁移为 `*_v1_legacy`，不静默删除 |
| 游戏存档 | `state.version` 单调递增，加载时归一化并向后兼容 |

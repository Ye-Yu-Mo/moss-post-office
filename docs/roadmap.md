# 路线图（2026-11-26 起）

目标顺序：**先把好友和留存做出来，再做收藏品，最后才碰货币。**
估期按 1 人 + AI 辅助，包含测试和部署；链上部分必须先过 gate，不按日期硬上。

## W1：好友基础（已提前完成 2026-11-26）

- `friend_code`：6 位人类可读码，账号唯一；可复制/刷新。
- 好友关系：申请 → 接受 → 双向好友；不做单向关注（NPC 除外）。
- 好友列表：在线状态、邮票、远行胜场、最近活跃。
- 好友档案：只对好友可见，展示邮册完成度、明信片收藏、最近一张明信片。
- 好友明信片：从好友列表直接寄；每天最多 5 张；真人之间不带资源礼物，避免刷。
- NPC：可以直接「关注」8 位镇口邮差，不需要申请。
- 隐私：档案可见性开关；黑名单/删除好友。
- 验收：两个账号互加、互寄、串门、删除；服务端测试覆盖权限。

## W2：社交留存（已提前完成 2026-11-26；后院选种/浇水/稀有种子/扩地/好友浇水/偷菜纸条/图鉴来访/每日订单为追加）

- NPC 每日来信：按日期/天气生成一封，主题不同，附小额材料。
- 明信片套装：镇口、星港、雾湖、雨夜四套；集齐给月光邮戳/材料。
- 串门动作：去好友邮局留一枚访客邮戳（每日 1 次），不产生资源。
- 未读提醒：镇口按钮红点、好友申请红点。
- 好友动态：谁收了新明信片、谁完成了远行（只展示摘要，不暴露存档）。
- 验收：D1/D7 留存、好友添加率、明信片发送/领取率。

## W3：收藏品（链下，已提前完成基础签发）

- 用 AI 为明信片/纪念戳生成唯一插画；生成在服务端，记录 prompt、seed、图片 hash。
- `collectibles` 表：藏品 id、模板、edition、owner、minted_at、来源事件。
- 服务端签发「可领取凭证」，先只做站内收藏，不接钱包。
- 总量：每版固定 edition（例如 100/500），全局有上限；不增发。
- 图片存储：对象存储 + CDN；元数据 JSON；保留原图 hash。
- 验收：同一账号不能重复领取；超发会被拒绝；删除账号的处理策略明确。

## W4：链上准备（必须过 gate）

Gate：

1. 站点有 HTTPS（Caddy/Cloudflare Tunnel/平台证书），HTTP 不接钱包。
2. 收藏品在链下已经稳定，且不依赖链上才能玩。
3. 合规评估完成：目标地区、年龄、是否允许转让、是否涉及金融属性。

技术：

- 钱包签名登录（SIWE 或同等方案），不接触助记词、不托管私钥。
- 测试网合约（ERC-721/1155），每版固定上限；默认 soulbound（不可转让），如要转让单独评审。
- 元数据放 IPFS/Arweave 或带 hash 的对象存储；合约只存 tokenURI。
- 铸造由服务端签名凭证触发，客户端不能自行 mint。
- 领取页可作为可选入口，不影响游戏主流程。

## W5：链上装饰收藏品

- 只发装饰性收藏品：明信片、纪念戳、活动卡面。
- 不绑定数值、不掉落、不影响远行/订单/挂机。
- 主网先小流量；总量、版数、铸造窗口公开。
- 不做官方二级市场、不承诺升值、不做现金兑换。

## W6：货币实验（可选，默认不做）

只有当以下全部满足才考虑：

- 服务端权威账本（不能再用客户端存档当余额）。
- 固定总量、不可增发、合约权限最小化、多签/时间锁。
- 不做现金兑换、不做官方交易市场；默认不可转让或严格限制。
- 法律/税务/地区限制/年龄门槛评估完成。
- 安全审计、监控、应急冻结/回滚方案。
- 货币不能成为游玩前置；非链上玩家必须完整可玩。

不满足就不做；装饰收藏品已经足够承载「拥有感」。

## 衡量指标

- D1 / D7 留存、好友添加率、好友明信片发送/领取率、串门率、明信片套装完成率。
- 先证明留存，再做链上；不要用链上热度替代玩法留存。
